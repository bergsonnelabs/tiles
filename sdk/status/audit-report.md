# Cores SDK End-to-End Audit Report

> **Superseded (kept for history).** This April 2026 report is mostly stale and partly wrong
> (it claims SAI on the L4 and H5, and AES on the H5). The current findings are the portal page
> "Core.ST SDK audit and priority list, September 2026" (SDK project), and the live per-Core
> status is `core-*.json` in this folder.

> 2026-04-06 — RM → Tile JSON → Coregen → LL → HAL → Core → Configurator → Docs
> Covers STM32L011E4 (Core.ST.L0), STM32L422TB (Core.ST.L4), STM32WBA55HGF6 (Core.ST.W5), STM32H523HE (Core.ST.H5)

---

## How to Read This Report

Each subsystem is traced across every layer where it appears. Findings are tagged:

- **[BUG]** — Incorrect behavior, wrong data, or crashes
- **[GAP]** — Missing functionality or validation
- **[INCONSISTENCY]** — Works but inconsistent across cores or layers
- **[SYNC]** — Data out of sync between repos or files
- **[CLEANUP]** — Code quality / documentation issues

## 1. CLOCKS

| Layer | Status |
|-------|--------|
| Tile JSON | Clock configs present on all 5 tiles |
| Coregen | `build_clock_config()` + `solve_pll()` |
| LL | `ll_rcc.h` — heavy per-family branching |
| HAL | None (clock init is generated) |
| Core | `core_clock_init()` generated by coregen |
| Configurator | Clock picker reads tile JSON configs |
| Docs | Implementation page tracks HSI/HSE/MSI/PLL |

**Findings:**

- **[BUG] Core.ST.H5 clock source mislabeled**: Tile JSON `Core-ST-H5-1-a.json` labels the 64 MHz internal RC as `"type": "hsi16"`. The H5 has HSI at 64 MHz, not 16 MHz. The description acknowledges this ("64MHz internal RC (HSI on H5)") but `type: "hsi16"` is wrong. Coregen and the Configurator both key on this string.

- **[BUG] L0 PLL modeled as M/N/R**: `MCU_DB` for L011 uses the L4-style PLL topology (M, N, R dividers) but the L0 has a simpler MUL/DIV PLL. `solve_pll()` iterates N continuously, which could pick values (e.g., N=9) that don't correspond to valid `PLLMUL` settings ({3,4,6,8,12,16,24,32,48}). Works by accident for 32 MHz (16×4/2) but is architecturally wrong.

- **[BUG] H5 PLLR artificially restricted**: `r_values` is `[1,2,3,4,5,6,7,128]`. RM0481 allows R from 1 to 128. Missing R=8 through R=127 means the solver can't reach some valid frequencies.

- **[GAP] H5 VCO mode selection**: VCO min of 150 MHz corresponds to medium-range mode; wide-range is 192-836 MHz. Code doesn't select VCO mode — could produce invalid configs in the 150-191 MHz dead zone.

- **[INCONSISTENCY] `ll_rcc_hsi16_enable()` naming**: Function is named "hsi16" on all cores, but on H5 it enables a 64 MHz oscillator. Comment says "called HSI16 for coregen compatibility."

- **[GAP] APB2 prescaler set on L0**: `core_init.c.j2` emits `ll_rcc_set_apb2_div()` unconditionally, but L011 has no APB2 bus.

- **[GAP] Max frequency 248 vs 250**: Core.ST.H5 `max` config achieves 248 MHz. The IC supports 250 MHz. PLL R values 8+ would allow reaching 250.

## 2. GPIO / PADS

| Layer | Status |
|-------|--------|
| Tile JSON | Pads with functions on all tiles |
| Coregen | `core_pads.h` generated per tile |
| LL | `ll_gpio.h` — no family guards (universal) |
| HAL | `hal_gpio.h` — thin wrapper |
| Core | `core_pad.h` — pad-centric API |
| Configurator | GPIO section, pad assignment UI |

**Findings:**

- **[BUG] SPI1.M0SI typo**: Core-ST-L4-1-a.json and Core-ST-L4-2-a.json pad 2 has `"SPI1.M0SI"` (zero instead of letter O). This will cause coregen to fail when trying to match the function for SPI MOSI assignment.

- **[BUG] TIM171.N malformed**: Core-ST-W5-b.json pad 11 has `"TIM171.N"` instead of `"TIM17.1N"`. References a non-existent timer.

- **[INCONSISTENCY] ADC naming**: Core.ST.H5 uses differential-style `ADC7+`, `ADC3-`. All others use `ADC3`, `ADC12`. Coregen's `extract_adc_channel()` handles both but the inconsistency could confuse users.

- **[INCONSISTENCY] SPI1.SCK vs SPI1.CLK**: Core.ST.H5 pad 9 uses `SPI1.SCK`; all other tiles use `SPI1.CLK`. The interface pad_assignment references `SPI1.CLK`, so the names don't match.

- **[INCONSISTENCY] Comparator naming**: Core.ST.L0 uses `COMP1.IN+`; Core.ST.L4 uses `COMP1.+`. Inconsistent across tiles.

- **[INCONSISTENCY] USART prefix missing**: Core-ST-L4-1-a.json USART1 pad_assignments use short names (`TX`, `RX`) without the `USART1.` prefix. Core-ST-L4-2-a.json uses the full form.

- **[INCONSISTENCY] Digital pin naming**: Core-ST-L4-2-a.json pad 21 uses `"PH3"` (with port prefix); Core-ST-L4-1-a.json pad 11 uses `"H3"` (without).

- **[GAP] Missing `is_default`**: Core-ST-L0-1-a.json pad 9 digital function B0 lacks `"is_default": true`.

- **[GAP] Missing `is_required` flags**: Core.ST.L0 has no `is_required` on any interface pad_assignment. Core.ST.W5 missing on SPI and USART. Others have them.

## 3. ADC

| Layer | Status |
|-------|--------|
| Tile JSON | ADC channels on pads |
| Coregen | ADC channel extraction, analog pad init |
| LL | `ll_adc.h` — 4 different ADC IPs |
| HAL | `hal_adc.h/.c` — unified API |
| TAL | `tal_adc.h` — pad-to-channel resolution |
| Core | `core_adc.h` — user API |
| Configurator | ADC channel picker per pad |
| Status | raw/mv/temp/res/oversamp verified on U/H; raw/mv/oversamp on W |

**Findings:**

- **[BUG] ADC_14BIT phantom macro**: `core_adc.h` defines `ADC_14BIT = HAL_ADC_RES_14BIT` but this enum value doesn't exist in `hal_adc.h` (which only goes to 12-bit). Will cause compile error if used. H523 is 12-bit only.

- **[BUG] Core.ST.L0 COMP2 referenced but doesn't exist**: Core-ST-L0-1-a.json references COMP2 on multiple pads, but the STM32L011E4 (Cat 1) does not have COMP2. These pad functions are wrong.

- **[INCONSISTENCY] `hal_adc_init_simple()` hardcodes 80 MHz**: Deprecated shim uses 80000000UL as SYSCLK, which is only correct for Core.ST.L4.

- **[INCONSISTENCY] `hal_adc_read_pad()`/`hal_adc_read_pad_mv()` deprecated but present**: Marked `@deprecated` in comments but no compiler deprecation attributes. Users may still discover and use them.

- **[GAP] VREFINT on H5**: Status notes "returns wrong values, bypassed with nominal 3.3V." The `hal_adc_read_vdda_mv()` workaround needs investigation.

- **[GAP] ADC temp on W**: Status says "partial" — OTP cal not bus-accessible on WBA55, uses datasheet constants with ~±15°C accuracy.

- **[GAP] ADC watchdog**: Not implemented on any core. Hardware supports 1 (L0) or 3 (L4/H5) analog watchdogs per ADC.

- **[GAP] ADC injected channels**: Not implemented. L4 and H5 support up to 4 injected channels with dedicated data registers.

- **[GAP] ADC dual mode**: L422 has ADC1+ADC2, H523 has ADC1+ADC2. No dual-mode support.

## 4. DAC

| Layer | Status |
|-------|--------|
| Tile JSON | DAC1.OUT on Core.ST.H5 pad 9 only |
| Coregen | `dac_enabled` flag from pad scan |
| LL | `ll_dac.h` — H5 only |
| HAL | `hal_dac.h` — H5 only |
| Core | `core_dac.h` — H5 only |
| Configurator | DAC toggle shown only for Core.ST.H5 |
| Status | Verified on Core.ST.H5 |

**Findings:**

- **[BUG] ll_dac.h comment/code mismatch**: All function docs say "channel 1" but code operates on channel 2 registers (DAC_DHR12R2, DAC_CR_EN2). PA5 is DAC1_OUT2, so the code is correct but docs are wrong.

- **[BUG] hal_dac.h ignores channel field**: `hal_dac_t` has a `channel` member but all functions ignore it and hardcode channel 2. Multi-channel aspirational design is non-functional.

- **[GAP] Silent absence on non-H cores**: Including `core_dac.h` on Core.ST.L0/L4/W5 produces an empty header. No `#error` or `#warning`. User gets unhelpful "undefined reference" linker error.

- **[GAP] DAC noise/triangle generation**: H5 DAC supports hardware noise and triangle waveform generation. Not implemented.

- **[GAP] DAC sample-and-hold**: H5 DAC can hold output in Stop mode using LSI/LSE. Not implemented.

## 5. SPI

| Layer | Status |
|-------|--------|
| Tile JSON | SPI interfaces on U/W/H (not L) |
| Coregen | `build_spi_config()`, SPI_CLK_MAP |
| LL | `ll_spi.h` — two completely different IPs |
| HAL | `hal_spi.h/.c` |
| Core | `core_spi.h` |
| Configurator | SPI section (hidden for Core.ST.L0) |
| Status | Compile on U/H, partial on W (CSTART bug) |

**Findings:**

- **[BUG] SPI v2 CSTART transfer broken on W**: Status says "SPI v2 transfer sequence (CSTART/TSIZE) needs RM study — loopback times out on RXP." This blocks ALL SPI tiles on Core.ST.W5.

- **[BUG] SPI_CLK_MAP incomplete**: Missing SPI3 for L422 and SPI2 for H523. If any tile exposes these instances, coregen will error during generation (not validation).

- **[BUG] Core-ST-H5-1-a.json SPI1 interface pads swapped**: MISO and RDY are assigned to wrong pads (pad 2 should be RDY, pad 3 should be MISO per pad functions).

- **[INCONSISTENCY] SPI v2 performance**: `ll_spi_transfer()` on WBA/H5 disables+re-enables SPE per byte with TSIZE=1. Multi-byte transfers are O(n) SPE toggles — extremely slow.

- **[GAP] SPI DMA**: `hal_spi_xfer_dma()` always returns `HAL_ERROR`. Not implemented on any core.

- **[GAP] SPI IRQ**: Not implemented. All transfers are polled.

- **[GAP] SPI slave mode**: Not implemented.

- **[GAP] Coregen SPI auto-init**: Compile-only on all cores. Needs same treatment as I2C got.

## 6. I2C

| Layer | Status |
|-------|--------|
| Tile JSON | I2C interfaces on all tiles |
| Coregen | `build_i2c_config()`, I2C_CLK_MAP, timing |
| LL | `ll_i2c.h` — universal I2C IP |
| HAL | `hal_i2c.h/.c` |
| Core | `core_i2c.h` |
| Configurator | I2C section with speed picker |
| Status | std/fast verified on U/W; compile on L/H |

**Findings:**

- **[BUG] Core-ST-H5-1-a.json I2C3 pad_assignments CLK/DAT reversed**: Interface says pad 2 = I2C3.DAT and pad 3 = I2C3.CLK, but pad functions show pad 2 = I2C3.CLK (AF4) and pad 3 = I2C3.DAT (AF9). The pad functions match the H523 datasheet; the interface assignments are wrong.

- **[BUG] FMP on L422 may not work**: `ll_i2c_init_fmp()` sets CR1.FMP, but this bit may be reserved on L4. L422 FMP requires SYSCFG register manipulation to enable 20 mA GPIO drivers.

- **[GAP] I2C IRQ-driven**: Not implemented. All transfers are polled.

- **[GAP] I2C DMA**: Not implemented. Architecture has `TILE_FLAG_DMA_COMPLETE` reserved.

- **[GAP] I2C 10-bit addressing**: Not implemented.

- **[GAP] I2C SMBus**: Not implemented.

- **[GAP] I2C slave mode**: Not implemented.

- **[GAP] Coregen missing required-signals check**: Can configure I2C1 with CLK but no DAT — no warning.

## 7. UART / Serial

| Layer | Status |
|-------|--------|
| Tile JSON | USART/LPUART interfaces on all tiles |
| Coregen | Interface defines only (no init generation) |
| LL | `ll_uart.h` — per-family instances |
| HAL | `hal_uart.h/.c` |
| Core | `core_serial.h` |
| Configurator | UART section |
| Status | Polling verified on L/U/W; compile IRQ all |

**Findings:**

- **[BUG] LPUART type not recognized by Configurator**: `deriveCoreConfig()` filters `type === 'USART' || type === 'UART'` but LPUART1 has `type: 'LPUART'`. Core.ST.L0's LPUART1 is silently dropped from the UI.

- **[BUG] Core-ST-L4-2-a.json USART2.CK missing from pad 19**: Interface references pad 19 for USART2.CK but pad 19's function list doesn't include it. Per L422 datasheet, PA4 is USART2_CK at AF7 — the pad function is missing.

- **[GAP] UART DMA**: `hal_uart_tx_dma()` always returns `HAL_ERROR`. Not implemented.

- **[GAP] UART auto-init from coregen**: I2C and SPI get init code in `core_init.c`. UART only gets `#define` config constants. Manual peripheral init required.

- **[GAP] LPUART low-power wake**: Compile-only everywhere. Key for ultra-low-power designs.

- **[GAP] No TAL layer for UART**: ADC and Timer have pad-centric TAL wrappers; UART still requires explicit instance/pin configuration.

- **[INCONSISTENCY] Core-W missing USART1 interface**: WBA55 has USART1 but it's not in the tile JSON (board layout choice — noted as INFO).

## 8. USB

| Layer | Status |
|-------|--------|
| Tile JSON | USB interface on Core.ST.L4 and Core.ST.H5 |
| Coregen | `usb_enabled` flag, HSI48/CRS init |
| LL | `ll_usb.h` (L4) + `ll_usb_drd.h` (H5) |
| HAL | `hal_usb_cdc.h/.c` |
| Core | `core_usb.h`, `core_usb_hid.h` |
| Configurator | USB toggle (U/H only) |
| Status | CDC verified on U; CDC+HID verified on H |

**Findings:**

- **[BUG] Core-ST-H5-1-a.json USB.SOF wrong pad**: Interface says pad 3 = USB.SOF, but pad 2 has USB.SOF (AF10). Pad 3 has no USB.SOF function.

- **[GAP] No USB availability validation in coregen**: `usb_enabled` is blindly read from config.json. A project targeting Core.ST.L0 with `"usb": {"enabled": true}` would generate HSI48/CRS init code that won't compile.

- **[GAP] Silent absence on L/W**: Including `core_usb.h` on Core.ST.L0 or Core.ST.W5 produces an empty header. No `#error` or `#warning`.

- **[GAP] Fault dump H5 missing**: `hal_fault.c` USB register dump is L422-only. H5 (which also has USB) only gets LED SOS, no USB output.

- **[GAP] USB MSC**: Not implemented.

- **[GAP] USB Host mode**: H5 has DRD (Device+Host) but only Device is implemented.

- **[GAP] USB BCD (battery charging detection)**: L422 and H5 support BC 1.2. Not implemented.

## 9. BLE

| Layer | Status |
|-------|--------|
| Tile JSON | No explicit BLE interface (radio, not pin-routed) |
| Coregen | BLE gated by Makefile, not coregen |
| LL | None (uses ST BLE middleware) |
| HAL | None |
| Core | `core_ble.h/.c` |
| Configurator | BLE toggle (W only, from SDK status) |
| Status | Adv/GATT verified on W; stashed on `pre-ble` branch |

**Findings:**

- **[BUG] No compile-time guard on core_ble.h**: Header has no `#if defined(STM32WBA55xx)`. Including it on Core.ST.L0/L4/H5 compiles the declarations, then linking fails with missing BLE middleware symbols. Should be a clear `#error`.

- **[GAP] BLE detection in Configurator uses SDK status, not tile JSON**: `coreDef.ble` is derived from `features['ble.adv'] !== 'na'` in the SDK status file. If status data diverges, BLE detection breaks.

- **[GAP] No `peripherals` field in tile JSON for BLE**: BLE can't be inferred from pads/interfaces. Needs an explicit declaration.

## 10. TIMERS / PWM

| Layer | Status |
|-------|--------|
| Tile JSON | Timer functions on pads |
| Coregen | `extract_timer_channels()`, timer pad defines |
| LL | `ll_tim.h` — per-family instances |
| HAL | `hal_timer.h/.c` |
| TAL | `tal_timer.h` — pad-to-timer resolution |
| Core | `core_timer.h`, `core_pwm.h` |
| Configurator | PWM/capture pad picker |
| Status | tick/PWM/capture verified on L/U/H |

**Findings:**

- **[BUG] TIM6/TIM7 IRQ number missing on H5**: `hal_timer.c` `_tim_irq()` returns 0 for TIM6 and TIM7 on H523. IRQ 0 is WWDG on H5. Tick callbacks on these timers would enable the wrong interrupt.

- **[BUG] Core-ST-W5-b.json TIM171.N**: Already noted under GPIO — `"TIM171.N"` should be `"TIM17.1N"`.

- **[GAP] Timer one-shot mode**: Not implemented. Simple OPM bit setting.

- **[GAP] Timer encoder mode**: Not implemented. Hardware quadrature decoder.

- **[GAP] LPTIM**: Not implemented on any core. Runs in Stop mode — key for periodic low-power wakeup.

- **[GAP] TIM1/TIM8 advanced features**: Complementary PWM with dead-time, break inputs, hall sensor interface. Not implemented.

- **[GAP] Configurator PWM pad conflict**: `padIsClaimed()` does NOT check `state.pwmOutputs`. A pad can be assigned to both PWM and I2C simultaneously.

## 11. POWER / SLEEP

| Layer | Status |
|-------|--------|
| LL | `ll_pwr.h` — per-family |
| Core | `core_power.h` |
| Configurator | No power mode config UI |
| Status | Sleep all; Stop verified U/H; Standby verified U |

**Findings:**

- **[BUG] `core_standby_until_on_change()` UB on non-L422**: On L0/WBA/H5, function casts parameters to void then hits `__builtin_unreachable()`. This is undefined behavior — the compiler may eliminate surrounding code or cause crashes.

- **[BUG] Duplicate watchdog APIs**: `core_power.h` defines `core_watchdog_start(uint32_t seconds)` (1/2/5/10s). `core_watchdog.h` defines `core_watchdog_start(uint32_t timeout_ms)` (milliseconds, auto-prescaler). Both are `static inline` with different implementations. ODR violation if both included.

- **[GAP] Stop mode on L**: Hangs — RTC wakeup still not firing despite CSR offset fix.

- **[GAP] Stop mode on W**: Compile-only, not hardware tested.

- **[GAP] Standby on H**: Compile-only, not hardware tested.

- **[GAP] Low-power run mode**: L0 and L4 support sub-2 MHz operation with low-power regulator. Not exposed.

- **[GAP] Shutdown mode**: L4 supports lowest-power mode (below Standby). Not exposed.

- **[GAP] PVD (programmable voltage detector)**: L0 and L4 have it. Brown-out warning for battery devices. Not implemented.

## 16. CROSS-REPO SYNC

**[SYNC] features.json completely diverged**: tiletown and cores repo have different feature group organization, different feature IDs (`usb.cdc` vs `conn.usb_cdc`, `ble.adv` vs `conn.ble_adv`, `i3c.ctrl` vs `adv.i3c_ctrl`), and different feature counts. **Tiletown is the authoritative version.**

**[SYNC] Core.ST.W5 SDK status diverged**: tiletown has ~50 additional feature entries plus different status values (e.g., `i2c.fmp: compile` vs `na`, `adc.temp: verified` vs `partial`).

**[SYNC] Tile JSONs partially out of sync**: tiletown copies have `bootloaders` arrays and JTAG annotations not present in cores repo. Cores repo is behind.

**[SYNC] Core-ST-L4-2-a.json LPUART1 pad error**: Interface references pad 16 for LPUART1.RTS_DE, but the function exists on pad 15.

---

## 17. COREGEN

**[BUG] config-schema.json stale**: Schema defines `clock` as object but all real projects use a string. Schema uses `pins` but code uses `pads`. Missing `tiles`, `usb`, `ble`, `programming` sections entirely.

**[GAP] No USB availability validation**: `usb_enabled` read from config.json with no check that the tile has USB.

**[GAP] No conflicting pad assignment detection**: Same pad can be assigned to multiple functions.

**[GAP] No peripheral instance validation**: I2C2 on Core.ST.L0 would fail at generation, not validation.

**[GAP] No required-signals check**: I2C with CLK but no DAT passes validation.
